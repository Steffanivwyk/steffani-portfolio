## How I approach systems work

I do not start with the tool. I start with the business process.

Before automating, I define:

1. what the source of truth should be,
2. which data actually needs to move,
3. who owns each stage,
4. what should happen when something fails,
5. what should remain approval-gated,
6. and what leadership needs to see in order to make a decision.

That approach keeps automation useful, explainable and maintainable.
